# L2 — the engine

Status: **authoritative**. Describes `crates/engine` as it is today.

L2 is a small, **generic** game engine: the layer system (scene graph), the
bitmaps, the mixer, the video overlays, the timers, the text engine, the
storage namespace, the input state and the frame. It owns **all** the engine
state; it performs actions on the stateless L1 services.

L2 carries **no TVP/TJS vocabulary**: no `LT_*`, no `TVP_*`, no
virtual-key codes, no `.sli` fields, no `0..100000` volume scale, no KAG
tags. A blend is the generic `api::blend::BlendMode`; a gain is normalized; a
key code is an opaque integer.

---

## 1. The crate surface

`crates/engine` is `#![forbid(unsafe_code)]` and `#![warn(missing_docs)]`.

| `projection` | the seam: `Scene` → `RenderScene` |

| `layer_ops` | layer composition and pixel-region operations (blits, fills, masks, blur, gamma, subtree render) |

| `trans` | the transition state machine |

## 2. The logical layer tree

`engine::scene::Scene` is the whole logical scene and all of its state.

| field / type | role |
|---|---|
| `windows: Vec<WindowState>` | one entry per `Window`: `inner_size`, `visible`, `opacity`, `primary_layer`, the focused layer, focus domains, the layer list |
| `layers: Vec<LayerState>` | the layer nodes: `window`, `parent`, `rect` (x/y/w/h), `visible`, `opacity`, `blend`, `bitmap` (the main image), `image_left/top/width/height`, `hold_alpha`, `cache_bitmap`/`cache_enabled_count`, `transition_self`, and every TVP property L3 writes |
| `bitmaps: Vec<BitmapState>` | CPU RGBA pixels plus the dirty flags; the texture source. A bitmap may be **pending**: its pixels are still being decoded |
| `fonts: Vec<FontState>` | parsed faces |
| `structure_revision: u64` | bumped on every change the projection reads: windows, layers, their order/parenting/geometry/draw properties, and bitmap create/remove/resize |
| `content_revision: u64` | bumped on every bitmap pixel write |

`Scene` keeps private id→index maps and a decoded-image cache. It holds no
globals, no locks and no hidden caches; the projection is a pure function
over it.

The two revisions are what let an animated frame paint without re-projecting:
a bitmap content write moves `content_revision` only, so the engine uploads
the new pixels into the existing texture and reuses the projected tree. A
bitmap whose *size* changed is structural, because the projection reads its
dimensions.

### The pending bitmap

A bitmap may be **pending**: `BitmapState::pending` holds the decode future
of an image whose pixels have not landed yet. A pending bitmap carries the
**probed** dimensions — the header probe ran on the calling thread — and no
pixels. The decode result lands in it when the scene resolves it (§9), and
every read of the pixels waits for that resolution.

A decode that **failed after** the probe does not raise: the resolution
installs a fully transparent blank of the probed size and logs the failure.
The script has already returned from the load, so there is no call to fail.
A **probe** failure is different: the probe runs on the calling thread, so it
raises at the load, the way a load failure raises there.

### Draw order

`Scene::window_layer_order(window)` returns the window's layers
**parent-first**, which is what lets the projection compose ancestors in a
single forward pass. It is built from one O(n) pass over the window's layers
(the old implementation re-scanned the whole layer table per layer, which was
O(n²)), then a sibling sort per level.

* The root list is the layers the window actually owns. A layer whose parent
  was severed is deliberately **not** adopted: the draw order is the tree
  reachable from the window's primary layer, so a `Part()`ed layer stops
  being drawn and hit-tested.
* Only layers reachable from those roots are emitted. Shutdown layers are
  excluded from the walk entirely, so they can never be discovered.
* Sibling order is the layer's order index; the absolute-order mode lets a
  layer take an explicit index in its parent.

## 3. The projection — the L2↔L1 seam

Rendering is the collapse of two trees that live in different layers:

```
  L2  logical tree      engine::scene::Scene          (owns every property)
        │
        │  projection — engine::projection::project_scene / project_window
        │  a pure field copy; NOT a draw list, no batching, no sorting
        ▼
  L1  draw tree         render::scene::RenderScene    (an arena of RenderNode)
        │
        │  the single draw action — render::render(pipeline, surface, state, scene)
        ▼
  L1  backend           null: null.rs + cpu.rs   ·   vulkan: vulkan/mod.rs + draw.rs
```

`project_scene_report(scene, texture)` (or `project_window_report` for one
window) produces a `ProjectionReport`: the `RenderScene` plus `drawn_layers`,
the layer ids whose pixels the pass actually emitted. The texture table is
supplied as a closure (`|id| textures.get(&id).cloned()`), so the projection
is testable without a GPU.

### Composition

`compose_layer` walks the ancestor chain and accumulates:

* **position** — the `x`/`y` origins accumulate (saturating) through the
  chain while the layer keeps its own `w`/`h`: a child is positioned relative
  to its parent but owns its size;
* **opacity** — the product of the layer and every ancestor, each clamped to
  `[0, 1]`, with NaN mapped to 0;
* **visibility** — the AND of the chain;
* **clip** — the intersection of the layer's own absolute rectangle and every
  ancestor rectangle, including texture-less container layers.

A cross-window `parent` link, an invalid link or a cycle stops the chain.
The chain length is bounded by the layer count, so a cycle is detected
without a per-call set.

### Parent linking

The node's `parent` is its nearest **drawn** ancestor's node, or the scene
root. A skipped layer passes its own nearest-drawn ancestor down, so its
children still attach correctly.

### Clip

Each node's clip is the intersection of its own absolute rect and every
ancestor rect, matching the reference's `r ∩ Rect` and its child
intersection. A zero-sized intersection emits no node. The primary layer's
clip is the window's client size rather than its own rect.

### Sprite placement

`visible_image_region` resolves `Layer.rect` plus
`ImageLeft/Top/Width/Height` into a destination `RectF` (window coordinates)
and a source `PixelRegion` (bitmap pixels), clipped to the layer rect. A
negative `ImageLeft` selects a sprite-sheet frame. A fully clipped image
produces no node.

### Content, cache and order

* **Content** — today only `RenderContent::Texture` is emitted: the layer's
  `bitmap`, or its rendered `cache_bitmap`, or its transition
  `transition_self` image (which stands in for the layer's own image while
  its children keep drawing live). Solid fills and glyph runs are not
  produced by the projection.
* **Cache** — a layer that has enabled the subtree cache and has a rendered
  cache bitmap draws that bitmap instead of its own image, and its
  descendants are covered by it: a cached ancestor already contains those
  pixels, so they contribute no node of their own. The flag propagates down
  the subtree. A cached ancestor's subtree composition takes the same self
  image in place of the layer's main image, and a change to it invalidates
  that cache like any other drawn-image change. A layer whose cache is only
  *enabled* but has no cache bitmap yet (its subtree is trivial) draws
  normally. A layer owned by an active transition, or one whose subtree
  contains a whole-subtree transition, keeps drawing live.
* **Self image** — a transition that blends the layer's image with another
  layer's without consuming the subtree stores a self image that stands in
  for the main image. It covers only the layer's own image, so the layer
  never becomes a cached-subtree root and its children keep drawing live.
* **Order** — `z` comes from a per-scene monotonic counter, so siblings
  across all the windows of a scene are globally ordered by insertion (layer
  order).
* **Root/background** — one default root node; the background is opaque
  black. The root also carries the presentation transform; the layer nodes
  themselves stay in VM coordinates.

### What the projection deliberately does not do

No batching, no sorting, no transform nesting, no mask/province/face work.
Every projected layer node gets `transform = IDENTITY`; the root carries the
Fit presentation. The hierarchy exists for linking, `z`-order, the inherited
opacity/visibility and the ancestor clip. The counts of drawn / hidden / empty
/ clipped layers are trace-logged, so an almost-empty frame is diagnosable.

## 4. Presentation and the pixel-translation layer

The scene is described in VM pixels and drawn in device pixels; the host's
window client is a third space. This section is where those meet.

### The rule: fit with letterbox, only

* scale the VM scene **uniformly** by `s = min(device_w / vm_w, device_h / vm_h)`;
* place it **centred**, so the letterbox margin on the free axis is
  `(device − vm · s) / 2` per axis;
* clear the margin to the background colour.

There is no `game`/`fill`/`expand` mode and no configuration key on any
launcher. The scaling feature that once existed (a `ScalingMode` enum, a
`--scaling` flag, a whole-tree `ViewTransform`) was deleted rather than
adapted.

Degenerate inputs are not scaled around: a zero VM dimension or a zero device
dimension means there is no valid mapping. `PixelTranslation::fit` returns
`TranslateError::EmptyDimension`, and the engine skips the frame rather than
dividing by zero or substituting a synthetic scale of 1.

### The mapping

`engine::translate::PixelTranslation` is the pure, `Copy` value that owns the
mapping. It holds no clock and no cache; the engine recomputes it whenever
the VM size or the device size changes.

```rust
pub struct PixelTranslation {
    pub scale: f32,          // device pixels per VM pixel (min fit)
    pub offset: (f32, f32),  // device-space position of the VM origin
    pub vm_size: (u32, u32),
    pub device_size: (u32, u32),
}
```

It offers `to_device_point`, `to_device_rect`, `to_vm_point`, `raster_scale`,
`vm_pixel_region`, `root_transform` and `inverse_root_transform`.

### Where it is applied

* **Projection** — every drawn layer node keeps its VM-space `dst` and every
  rectangle clip. The engine writes the Fit mapping to the render-scene root
  as `scale(s, s)` then `translate(offset)`; layers keep their own transform
  in VM space and L1 composes the root during traversal. The render-only
  overlay is authored in device pixels, so its node carries the inverse root
  transform and stays at its authored position.
* **Input** — the composition root maps each pointer/touch position
  device→VM with `to_vm_point` **before** the VM tick, so L2's input state
  and L3's hit-test only ever see VM coordinates. Keyboard, wheel, text and
  focus events carry no position and pass through unchanged.
* **Readback** — `vm_pixel_region(x, y)` is the device region a VM pixel
  covers. The consumer is not wired yet (see §11).

### The boundary

* **L3 never sees a device coordinate.** Every value L3 reads
  (`System.screenWidth`, layer extents, `Font.getTextWidth`, `getPixel`) and
  every hit-test input is VM space.
* **L1 never interprets VM semantics.** L2 hands the pipeline a VM-space
  render tree whose root carries the Fit transform; L1 composes the transform
  and writes device pixels, but it does not know what the coordinates mean.
* **L2 owns the mapping** and is the only layer that names both spaces.
* The translation is **internal to L2**: L3 natives must not call
  `to_device_*`/`to_vm_point`/`raster_scale`, name a device pixel, or import
  `PixelTranslation`. The composition root only maps platform input through an
  L2 method.

At `s == 1` the mapping is the identity, so projection and input reduce to
the unscaled path and the reference is matched exactly. The device scale
switches on by itself when the window client and the logical screen differ —
the game's own window zoom, the Android surface, or a desktop window the
player resized.

### Window size

The logical screen is the primary layer. `Window.setInnerSize` changes the
**client** area only; the translation fits the unchanged screen into it. An
OS resize changes the framebuffer only and never writes back into the scene
window. A script window-size change travels the other way: the engine
surfaces it once through `Engine::take_window_resize` and the composition root
applies it to the desktop window.

## 5. The storage namespace

`engine::storage::Storage` owns the namespace: the game directory, the
mounted archives, the mount order, the auto-path list, the resolution cache
and the registered media table.

* `Storage::archives: Vec<MountedArchive>` in mount order. `find` walks it
  **in reverse**, so a later mount wins.
* `MountedArchive { path, file_name, backing, archive }` holds the parsed
  index (`Xp3Archive`, whose *type* is L1's and whose *value* is L2's) and
  the backing — a `FileState` (streaming) or a `Vec<u8>` image (preloaded).
* **Disk entries are not held.** A disk name is probed live each time
  resolution reaches it, and only a *hit* is cached, keyed by the requested
  name, matching the reference's auto-path cache. The auto-path candidate
  tables are cached separately: a `Folder` table of real children, or an
  `Archive` prefix table of base name → in-archive name. Both are dropped on
  any mount/unmount/auto-path change.
* `find` returns a `Location` — a lightweight reference *into* the held
  index, not an entry copy — so the read goes back through the archive.
* `find` returns `Result<Option<Location>, StorageReadError>`: "not found"
  and a genuine failure stay distinguishable.

### Mounting and precedence

```rust
pub fn mount_archives(
    fs: FileSystem,
    base_dir: impl Into<PathBuf>,
    archives: impl IntoIterator<Item = impl AsRef<Path>>,
) -> Result<Storage, MountError>;

pub fn mount_discovered_archives(
    fs: FileSystem,
    base_dir: impl Into<PathBuf>,
    archives: impl IntoIterator<Item = impl AsRef<Path>>,
) -> Result<Storage, MountError>;

pub fn discover_archives(
    file_system: &FileSystem,
    base_dir: &Path,
) -> Result<Vec<PathBuf>, StorageReadError>;
```

Each constructor has a `_with` variant that takes a `MountOptions` — the
choice between a streaming backing and a preloaded image. The plain
constructors keep the streaming backing. A single archive can also be mounted
after the fact with `Storage::mount_archive`, and removed with
`unmount_archive`.

* An explicit archive list is mounted in order and **later mounts win**.
* A **directory-only** launch — a positional directory or `--base-dir` with
  no `--archive` — opts into a recursive `*.xp3` scan. The scan is ordered by
  file name (case-insensitive, numeric-aware) and then by depth, so a root
  archive mounts last and overrides a nested one of the same name.
  Symbolic-link directories are not followed. Explicit `--archive` entries
  suppress the scan.
* A **scanned** archive that cannot be read or parsed is skipped with a
  warning, so one stray file cannot stop an otherwise playable mount. An
  **explicit** archive that cannot be read is a typed `MountError` — never
  skipped.
* `preload_archives` reads each mounted archive into memory at mount. The
  cost is the archive's own size in resident memory; there is no cap and no
  heuristic, the user opts in. A preload failure is treated exactly like a
  parse failure.

### Resolution order

`Storage::find` resolves a name in the reference's order:

1. explicit archive addressing — `foo.xp3>data/script.ks`; the archive is
   opened on demand when it exists but was not mounted;
2. **the current project storage** — the project archive for an archive
   project, the app directory for a folder project. The project archive is
   opened on demand when it is not mounted;
3. the auto-path list, last added first;
4. the remaining mounted archives, later mounts first;
5. the app directory as the loose-file fallback for an archive project.

`Storage::set_project` chooses between the two project kinds: a path that is
one of the mounted archives, or that stats as a non-directory on disk, is an
archive; anything else is a folder. A relative path is resolved against the
app directory, the same way `mount_archive` resolves it.

The code map is [`docs/code/engine/storage.md`](../code/engine/storage.md) §4.

### Startup discovery

`Storage::startup_plan` resolves the reference's order into a `StartupPlan`:

1. **`patch.tjs`** — app path only, no search; executed if it exists.
2. **`startup.tjs`** — searched across the storage (disk + mounted archives).
3. **`AfterStartup.tjs`** — app path only, if it exists.
4. If `startup.tjs` fails and `system/Initialize.tjs` exists, execute that.

If nothing is found, the result is a typed `StartupError` — never a
warn-and-continue.

The loader does not execute scripts: discovery is L2 (pure storage semantics,
testable without the VM) and execution is L3/L4.

## 6. Sound

`engine::sound` owns the mixer, the per-buffer and per-channel playback
state, the loop model and the decode-ahead stream.

* `Mixer` mixes; the host installs the L1 decoder through the `AudioStream`
  seam.
* L3 maps the script-visible `0..100000` volume scale to L2's normalized gain
  and never re-implements mixing.
* `LoopInfo` / `LoopLink` / `SoundLabel` / `LoopCondition` are the generic
  loop and label model; the `.sli` format parser and the `TVP_*` constants
  are L3.
* `SoundEvent` carries the status changes (`onStatusChanged`,
  `onFadeCompleted`) that L3 turns into script events.
* `mix` / `mix_source` are the pure mixing functions; the mixer converts a
  source to the output rate with a windowed-sinc kernel.

## 7. Video

`engine::video::VideoOverlay` owns the overlay playback machine: status,
clock, position, play rate, whole-stream and segment looping, period-event
state, the current decoded frame, the overlay binding and the pending event
stream.

* The host supplies the decoded frames; L2 does not call a codec.
* `blit_frame_to_layer` and `blit_frame_to_layer_opacity` compose the current
  frame into a layer (the `layer1`/`layer2` and mixing layer of the
  reference's video overlay).
* **Prepare mode ends when the caller says the picture is on screen.**
  `VideoOverlay::prepare` freezes the clock; the caller presents the frame,
  composites it, and only then calls `VideoOverlay::complete_prepare`, which
  queues the prepare event, pauses and rewinds. A frame delivered during
  prepare mode does not end it by itself.
* `VideoBounds`, `PlayStatus`, `VideoEvent`, `PeriodReason` and `VideoError`
  are the typed vocabulary; the script-facing names are L3's.

## 8. Text, timers, transitions, input

### Text

`engine::text` owns the shaping and layout caches, the registered font
faces, the glyph atlas and the coverage/blur caches.

* `TextEngine::add_font` takes the bytes L3 read from storage; `load_system_font`
  resolves a family from the system's font directories.
* `layout` produces a `TextLayout` of positioned glyphs; `rasterize_text_coverage`
  produces a VM-sized `CoverageMask`; `compose_text_into` composites the
  coverage into a layer bitmap.
* **Font sizes, glyph advances and text rects are VM pixels.** Every
  script-visible measurement (`Font.getTextWidth`, `getEscWidth`, …) is
  computed in VM units and returned unscaled.
* The glyph atlas is keyed in device units (raster size) so a scale change
  rebuilds it; a colour change does not, because coverage and tint are
  separate.

### Timers

The timer surface is deliberately small:

```rust
create_interval(interval_ms, callback) -> TimerId
set_interval(id, interval_ms)
set_enabled(id, enabled)
remove(id)
```

`TimerState::advance(now)` is called **only** by `Engine::frame`. It is still
public because the surface has not been collapsed yet. L3 decides whether to
arm at all and turns a fire into an `onTimer` post; the frame body drains the
posts the engine produced.

### Transitions

`engine::trans::Trans` owns the transition state machine — kind, duration,
elapsed phase, rule mask, completion — plus the scroll vocabulary. L3 stores
one machine per layer in its dispatch state and advances it from the frame
body.

* A whole-subtree transition blends into `ensure_transition_display`'s frame,
  drawn in place of the subtree.
* A transition that keeps its children live blends into
  `ensure_transition_self_image`'s image, drawn in place of the layer's own
  image, with the children still projected.
* **The two composition kinds are composited, not blended.**
  `Trans::transition_frame` returns the frame for `crossfade` and `scroll`:
  the two sources placed in one rectangle, with the fade source carrying the
  phase weight. The layer holds it in `LayerState::transition_frame` and the
  projection draws the two sources in place of the layer's image, so a GPU
  host writes no pixels and uploads no bitmap per tick. Every other kind
  needs a per-pixel rule or a coordinate warp, so it returns no frame and
  `Trans::apply` blends it.
* The teardown clears the slot through `Scene::set_transition_self_image(..,
  None)`; the slot is never part of the subtree cache, so releasing the cache
  leaves it alone.

### Input

`engine::input::InputState` owns the per-frame key/button/touch state, the
pointer position and visibility, the wheel delta, the text input, the
last-pressed list, the frame counter and the click-sequence window. L3 owns
only the event→state marshalling and the frame-boundary calls around it.

The pointer and touch positions in it are **VM pixels**: the composition root
has already mapped them from the device.

## 9. The frame

`engine::Engine` is the runtime. It holds the stateless L1 render objects the
composition root hands it, and every L2 value: the scene, the projected
`RenderScene`, the `Surface`/`RenderState` pair, the bitmap texture table,
the timer registry, the input state, the surface size, the frame clock and
the overlay.

```rust
pub fn step(&mut self, dt_ms: f32, hooks: &mut dyn GameFrame)
    -> Result<FrameReport, EngineError>;
pub fn frame(&mut self, now_ms: u64, hooks: &mut dyn GameFrame)
    -> Result<FrameReport, EngineError>;
pub fn resize(&mut self, size: (u32, u32)) -> Result<SurfaceEvent, EngineError>;
```

`frame` sets the clock rather than accumulating it, so a test can jump between
frames deterministically; `step` is the accumulating sugar. The delta handed
to the hook is the distance from the previous frame, and zero on the first
frame.

The order inside one frame:

1. set the clock; fit the presentation;
2. advance the timer registry;
3. run `hooks.before_render(now_ms, dt_ms)`;
4. wait for the pending image decodes — the image barrier;
5. fit the presentation again — the hook may have resized a window's primary
   layer;
6. refresh the render-only overlay;
7. upload the dirty bitmaps, prune the stale textures;
8. project the scene into the device-space `RenderScene`;
9. run `hooks.after_project(drawn_layers)`;
10. upload and project again if the hook changed the scene;
11. one `RenderPipeline::render` call.

The projection is skipped when the scene's `structure_revision` did not change
and neither the presentation mapping nor the texture table invalidated it.
A size pair that cannot be fitted skips everything that draws and reports no
frame statistics.

`FrameReport` carries the frame index, the elapsed time, the null-backend
counters, the upload/prune/project/render costs and the two projection passes
when a hook needed the second one. The drawn set is also available through
`Engine::drawn_layers()`.

### The image barrier

A load whose decode the pool took leaves a **pending** bitmap behind: the
image's size is known (the header probe ran on the calling thread) and its
pixels are still being decoded on a pool worker. The barrier is
`Scene::resolve_pending_images`, run right after the upward hook: it waits
for every pending image and installs its pixels, so the frame uploads and
draws decoded pixels.

* The wait is on each image alone, never on the pool. The decodes run
  concurrently, so the barrier costs the time the **last** decode needs
  rather than the sum of them.
* A waited-for image is **demanded**, and a worker takes a demanded job
  before an ordinary one, so a script's load is never delayed behind a
  prefetch backlog.
* A decode that failed installs a fully transparent blank of the probed size
  and logs the failure; a cancelled decode installs the same blank. Neither
  raises: the load already returned.

### The single upward edge

```rust
pub trait GameFrame {
    fn before_render(&mut self, now_ms: u64, dt_ms: f64) -> Result<(), String>;
    fn after_project(&mut self, drawn_layers: &[u32]) -> Result<(), String> { Ok(()) }
}
```

The trait is declared in L2 and implemented above it (the composition root's
`VmHook`). L2 never names L3 or L4.

### Re-entrancy

Callbacks mutate L2 state — they create layers, change intervals, advance a
transition — so a frame **collects due work first, then invokes**. The timer
advance is never re-entered mid-iteration, and a hook that changes the scene
is followed by a second upload and projection, so the frame draws the changed
state rather than the previous one.

## 10. The L3↔L2 protocol surface

`crates/compat/src/engine_api.rs` re-exports the engine items the
compatibility layer codes against. It is a **re-export, not a wrapper**: a
protocol type *is* the engine type.

| group | items | owns |
|---|---|---|
| `engine::scene` | `Scene`, `LayerState`, `BitmapState`, `FontState`, `Rect`, `DecodedImageKey`, `DecodedImageMode` | the logical tree, the pixel buffers and their cache keys, the fonts, the windows and focus domains |
| `engine::imagedecode` | `DecodePool`, `PendingImage` | the decode pool's worker threads, its queue and its byte accounting; the future a pending bitmap carries |
| `engine::storage` | `Storage`, `Location`, `StorageReadError`, `normalize_in_archive_name` | the mounted archive namespace, the auto-path list, the registered media table |
| `engine::input` | `InputState` | the per-frame input state |
| `engine::timer` | `TimerState`, `TimerId`, `TimerCallback` | the timer registry |
| `engine::text` | `TextEngine`, `TextError`, `FontId`, `TextStyle`, `CoverageMask`, `TextCoverageCache`, the coverage/composition functions | the layout and coverage caches, the faces, the atlas |
| `engine::sound` | `Mixer`, `AudioStream`, `SoundBuffer`, `SoundChannel`, `SoundSource`, `SoundError`, `SoundEvent`, `SoundLabel`, `LoopCondition`, `LoopInfo`, `LoopLink`, `Status`, `LOOP_FLAG_COUNT` | the mixer, the playback state, the loop state, the decode-ahead stream |
| `engine::video` | `VideoOverlay`, `VideoEvent`, `PlayStatus`, `VideoBounds`, `blit_frame_to_layer`, `blit_frame_to_layer_opacity` | the overlay playback machine |
| `engine::trans` | `Trans`, `TransKind`, `RuleMask`, `ScrollFrom`, `ScrollStay` | the transition state machine |
| `engine::raster` | `blend_pixel`, `fill_polygon`, `fill_rect_replace`, `flatten_arc`, `flatten_cubic`, `hatch_foreground` | nothing — pure functions over a `BitmapState` |
| `engine::layer_ops` | the blit/fill/mask/blur/gamma/subtree operations | nothing of its own — the layer and bitmap state is the `Scene`'s |

The rules the seam obeys:

* **No L1 service appears in it.** `FileSystem`, `RenderPipeline`, `Media`,
  `FontSystem` and the platform services are L1; L2 calls them internally and
  L3 never names one.
* **Every item is L2 state or an L2 action on that state.** L3 may construct
  an L2 state value as part of a native payload; the value stays L2-typed and
  lives in the one process-wide `CompatServices` binding, never in a second
  global.
* **Coordinates are VM pixels only.** A change that made a protocol item
  return or accept device coordinates would be a compatibility bug, not an
  internal refactor.
* **Errors are typed values.** `StorageReadError`, `TextError`, `SoundError`,
  `TransError` and `VideoError` are owned by the module that declares them.
  `Option` is used for an absent object (a layer or subtree that does not
  exist), and `()` for an infallible primitive that operates on already-
  validated VM bounds. A new failure mode is a new variant in the owning
  module's error enum, mapped at the L3 call site — never an `unwrap_or`, a
  wildcard arm that swallows a variant, or an L3-side substitute.

Adding an item: add or reuse it in `engine` with an L2-generic name,
re-export it in the right group, use it from L3 through `crate::engine_api`,
and record it. Removing one deletes it from the engine, the seam and every
call site in the same change.

## 11. Known gaps in L2

* **The mixer, video and non-self-updating transition pumps still run inside
  the L3 hook**, not in L2. `SoundState.clock` has not been retired for an
  L2-owned delta, and `Engine::run(clock, hooks)` does not exist because the
  platform loop still owns the event pump.
* **`TimerState::advance` is still public.** It runs only inside
  `Engine::frame`, but the surface has not been collapsed to the four
  methods.
* **Device-pixel readback is not wired.** `getPixel`, `piledCopy` and
  `saveLayerImage` read the CPU layer bitmap, which is VM-exact. The
  device-resolution backing and the `vm_pixel_region` consumer do not exist.
* **Glyphs are rasterized at VM resolution**, not at `size · raster_scale()`.
  The visible difference at `s > 1` is softness — a rasterization
  approximation, not a script-observable difference, because every layout
  metric stays in VM units.
* **Masks and province images are not emitted.** `Clip::Mask` and the
  main-vs-province composition are produced by neither the projection nor the
  backends; `hold_alpha` travels but is not interpreted.
* **Per-layer affine transforms are not projected.** The projection emits an
  absolute `dst` with an identity `transform`.
* **`Layer.face` is not read** by the steady-state projection; a
  `dfMask`/`dfProvince` layer is faithful only during a transition.
* **The frame still waits for the images it loads.** A decode the pool took
  runs on a worker, but the image barrier blocks the frame until every
  pending decode has landed (§9). The pool overlaps the decodes with each
  other, not with the frame that waits for them.
* **A load that cannot be deferred decodes on the VM thread.** That is the
  case when no pool is attached, when the load is a province load, and when
  the pool refused the job. A colour key is a worker pass, not a reason to
  decode synchronously. A transition that loads ~60 images serially on that
  path costs about 1.9 s.
* **A deferred decode enters the decoded-image cache.** The load consults
  the cache before submitting the job; when the scene resolves the pending
  image it stores the decoded pixels under the same key the synchronous path
  uses, so a later load of the same file is a cache hit. A failed, cancelled
  or malformed decode stores nothing.
* **`startup: images decoded` includes the deferred decodes.** The
  compatibility layer counts the synchronous codec calls and the application
  adds the pool's decode count and time before it logs the startup snapshot.
* **The decoded-image cache and the graphic cache limit** are L2 state, but
  the reference default disables them.
* **`BitmapState` carries no dirty region**, so a full-frame upload cannot be
  narrowed without a cross-cutting change.
* **The D35 directory-scan path is a folder project.** A directory launch resolves
  a relative `Storages.addAutoPath` against the app directory; an archive-only
  folder still boots through the mount stage, but archive-relative auto paths
  require an explicit single-archive launch (documented in
  `docs/code/engine/storage.md`).
* **`Storages.getFullPath` / `getPlacedPath`** return a normalized relative
  name or `arc>entry`, not the reference's full `file://domain/path`.
* **`Storages.addAutoPath`** raises a message that does not match the
  reference's `TVPMissingPathDelimiterAtLast` text.
* **`RenderContent::Glyphs`, `create_render_target` and `read_render_target`
  are not plumbed** from `engine` to `compat`, so a capture-style API has no
  path to a rendered texture.
