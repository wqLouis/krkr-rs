# L3 — the compatibility surface

Status: **authoritative**. Describes `crates/compat` as it is today.

L3 is the layer a game actually sees. It implements the KiriKiri script API
by **composing** L2 primitives, adapts platform events into TJS-visible
events, hosts the static native plugins, and emulates the Win32 environment
the games probe.

L3 is **thin glue**. Every native member should reduce to *marshal args → one
L2 call → marshal result*. If a member contains real logic — a loop, a state
machine, blending, timing, scheduling — that logic belongs in L2 unless it is
genuinely TVP-specific.

---

## 1. The crate surface

`crates/compat` is `#![warn(missing_docs)]`; the native ABI seam is the one
reviewed place where a file-level `#![allow(unsafe_code)]` is legitimate.

| module | role |
|---|---|
| `host` | `CompatHost` — installs the classes into the VM, owns the registry and the deferred-plugin activation |
| `ctx` | `CompatCtx` (the per-call context) and `CompatServices` (the process-wide binding) |
| `engine_api` | **the L3↔L2 seam** — the only file under `crates/compat/src` allowed to name `engine::` |
| `binding` | the one process-wide engine→context binding the C ABI forces |
| `event` | the event adapter: `PlatformEvent` → `TjsEvent` → script dispatch |
| `frame` | `run_frame_body` and the `FrameBody` trait — the per-frame poll order |
| `natives` | the native classes, the KAG parser, the plugin modules |
| `plugin` / `plugins_native` | the `NativePlugin` trait, `PluginRegistry`, `BUILTIN_PLUGINS`, `STARTUP_PLUGINS` |
| `null_plugin` | the null plugin object for a DLL that is not ported |
| `resource`, `storage`, `text` | the L3-side helpers (resource resolution, storage naming, text) |

## 2. The engine seam

`crates/compat/src/engine_api.rs` is the only file under `crates/compat/src`
allowed to contain `engine::`. The `l3-engine-api` rule in the `layering`
gate check reports any other file whose production code names the engine, and
its self-test proves the rule fires on a bad fixture and leaves a near-miss
clean.

The seam is a **re-export, not a wrapper**: a protocol type *is* the engine
type, so `CompatHost`/`CompatServices`' public signatures, the script surface
and the surface lock are unchanged. Behaviour changes belong in L2 or in L3's
marshalling, never in the seam file.

The full inventory — the engine items, the state each owns, the coordinate
space, the error type and the lifetime — is in [`l2.md`](l2.md) §10. The
rules the seam obeys:

* **No L1 service appears in it.** L3 never names a `FileSystem`,
  `RenderPipeline`, `Media` or `FontSystem`.
* **Every item is L2 state or an L2 action on that state.**
* **Coordinates are VM pixels only.** L3 never calls `to_device_*`,
  `to_vm_point` or `raster_scale` and never names a device pixel.
* **Errors are typed values** mapped at the call site; `Option` means "the
  object does not exist", `()` means "the primitive is infallible on
  validated VM bounds".

Adding an item: add or reuse it in `engine` with an L2-generic name,
re-export it in the correct group, use it from L3 through `crate::engine_api`,
and record it. Removing one deletes it from the engine, the seam and every
call site in the same change — no compatibility shim is kept.

## 3. The native classes

The registered surface matches the reference **per class**, not as a union:
`Layer` has 149 members, `Window` 91, `Bitmap` 19, `Font` 21, `Timer` 5 and
so on. The shared behaviour lives in the L2 `Scene` accessors; the L3 classes
are thin registrations that delegate to it. Where two classes genuinely share
a member, they share the Rust function or macro — never the registration list.

The tracked classes are `System`, `Storages`, `Scripts`, `Window`, `Layer`,
`Bitmap`, `Font`, `Timer`, `Debug`, `Plugins`, `VideoOverlay`,
`AsyncTrigger`, `MenuItem`, `WaveSoundBuffer`, `CDDASoundBuffer`,
`MIDISoundBuffer`, `KAGParser`, `Pad`, `Rect`, `Clipboard`, `ImageFunction`,
`BitmapLayerTreeOwner`, `BasicDrawDevice`, `PassThroughDrawDevice` and
`PhaseVocoder`.

**Native parity is 100% with empty allowlists** (0 missing, 3 intentional
extras: `KAGParser.multiLineTagEnabled`, `KAGParser.paramMacros` and
`PhaseVocoder.__TvpPhaseVocoder`). The report is a *coverage* measure — it
counts members present, not behaviour correct. See
[`../native_parity.md`](../native_parity.md).

### Win32 emulation

The games are Windows-native and probe Win32 APIs. `Window.HWND`,
`Window.drawDevice`, `Window.registerMessageReceiver`, the `System` Win32
members and the message loop must return **emulated** values and synthetic
stable handles — never a typed error. A typed error there is a compatibility
bug, not correct behaviour.

### The `void` / `null` distinction

TJS distinguishes `void` from `null`. A member with no value returns `null`
(`set_null_out`), not `void`: a script guard like `if (ret != null) ret.mode`
passes for `void` and then throws on the member access.

### A native property getter returns what the reference returns

A stored value whose constructor default is `void` must be mapped to the
reference's non-void value (an empty array, a dictionary, the class's own
object) before it reaches the script. A raw passthrough makes
`obj.prop.member` raise on a fresh object. The `void-getter` gate enforces
this; a reference property that genuinely reads back void is listed in
`scripts/allowlists/void_getter_allow.txt`.

## 4. KAG

`crates/compat/src/natives/kag` holds the parser (`parser.rs`), the tag
state (`state.rs`), the key/value preprocessor (`kvp.rs`) and the KAG layer
semantics. The parser is TJS-side: it produces script-visible values and
drives the L2 layer tree through the seam. The generic layer system it
operates on is L2's.

## 5. Plugins

### Static, built into L3

Native plugins are compiled into the binary. One table,
`natives::plugins::BUILTIN_PLUGINS`, maps a canonical DLL name (plus its
aliases) to that module's `register` function:

```rust
pub trait NativePlugin {
    /// The name scripts use: "menu.dll", "windowEx.dll", "fstat.dll", ...
    fn name(&self) -> &str;
    /// The modules this plugin loads when it activates (the reference's
    /// pre-registration hook).
    fn dependencies(&self) -> &[&str] { &[] }
    /// Register the plugin's native classes on the VM.
    fn register(&self, ctx: &mut CompatCtx) -> Result<(), CompatError>;
    /// Optional per-frame hook.
    fn poll(&self, _ctx: &mut CompatCtx) -> Result<(), CompatError> { Ok(()) }
}
```

The same table feeds `PluginRegistry::builtin()`, so `Plugins.link(name)`
recognizes **every** DLL that has been ported. `PluginRegistry::{plugin,
is_builtin}` query the table. `link` returns `void`, exactly as the
reference does.

### Registration happens at link time

Only the **startup surface** is on the VM before any script runs:
`natives::plugins::STARTUP_PLUGINS` holds exactly `xp3filter.dll`, the one
module the reference's `TVPLoadInternalPlugins` loads at startup
(`reference/cpp/core/plugin/PluginImpl.cpp:90-91`).

Every other built-in registers its native classes on the **first**
`Plugins.link` that names it. The timing is script-observable and is pinned
by a test: the shipped `system/voice.tjs` probes
`typeof WaveSoundBuffer.setDefaultAheads` before it links `getSample.dll`,
and only then publishes the `WaveSoundBuffer.enableGetSample` flag its
`onFlip` action reads. Registering that surface at startup makes the probe
true and the flag is published too early — the reference's own path depends
on the members being absent until the link.

A plugin may declare **dependencies** — the modules it loads when it
activates, the reference's `NCB_PRE_REGIST_CALLBACK`. The registry registers
each dependency first and does **not** report it in `Plugins.getList`:
`emoteplayer.dll` pulls in `motionplayer.dll`, and `getabout.dll` pulls in
`windowEx.dll` (which owns `System.getAboutString`).

**Plugin surface parity is 100% with empty allowlists** (56 tracked classes,
974 reference members, 0 missing, 0 extras). See
[`../plugin_parity.md`](../plugin_parity.md).

### The deferred plugin

`xp3filter.dll` is part of `BUILTIN_PLUGINS`, but its
`setXP3ArchiveExtractionFilter`/`ContentFilter` wrappers need the L2 storage,
which the composition root attaches after `CompatHost::install`.
`CompatHost::activate_deferred_plugins` completes the read of `xp3filter.tjs`
and installs the L2 filter seam **before** the startup scripts run — which
mirrors the reference, which loads `xp3filter.dll` before any game script.

### Autoload

The reference scans the exe directory, `<exe>/system` and `<exe>/plugin` for
`*.tpm` files, sorts them by name and links them (`foo.tpm` → `foo.dll`). The
composition root performs that scan and calls `PluginRegistry::autoload`.

### The null plugin object

Linux and Android cannot load the Windows DLLs the games name. When
`Plugins.link(name)` names a DLL that is **not** ported, L3 installs a **null
plugin object**:

* it accepts **every** member access and call;
* it returns void/undefined and does nothing;
* it logs a `warn!` per call and a `debug!` with the call name and arguments;
* it **never throws**.

Rationale: games call `Plugins.link` for plugins we cannot load; throwing
would make the game unplayable. This is the **single documented exception**
to the no-silent-fallback rule, and it is not silent — every call logs a
warning. The null path is only reached for a DLL that has **not** been
ported.

### Unported plugins and the DLL-surface pipeline

A plugin that has not been ported has no `reference/cpp` source, so the DLL
the game ships is the oracle, and a behaviour assertion cites it by build
hash and function: `plugins/<n>/plugin/<Name>.dll <sha256[:12]> @ <function
or address>`. The extraction pipeline and its measured fidelity live in
`plugins/analysis/`, validated against `layerExDraw.dll` (233 of 234 members
matched; the two differences were real build differences).

The DLLs are game binaries and are not committed, so **a test never loads one
at run time**: the extracted surface or behaviour is committed as a derived
fixture and the test gates on that.

## 6. Events and the frame body

### Event adaptation

```
platform event  →  L1 platform (winit / android-activity)
               →  L1 PlatformEvent
               →  L3 adapter (EventAdapter::map)
               →  L4 VM (dispatch to script handlers)
```

`EventAdapter::map` turns a `PlatformEvent` into a `TjsEvent`; `dispatch`
delivers it. L2 keeps the hit-test and focus state; L3 maps raw events to the
TJS event surface. No `#[cfg]` exists above L1.

Pointer and touch positions arrive in **VM pixels**: the composition root maps
them device→VM before the VM tick.

### The frame body

The engine owns the frame; the hook body is L3/L4's work:

```
L2: advance timers → invoke their callbacks (L3 posts onTimer)
L4/L3 hook: vm.tick (input begin → platform events → input end)
            → drain the posted onTimer events
            → sound_poll → video_poll → async_trigger_poll
            → continuous_handler_poll → idle compaction
            → frame_tail (movie poll + layer transitions)
            → audio drain
L2: overlay refresh → upload → project → L1 RenderPipeline::render
```

`compat::run_frame_body` does **not** fire timers and does **not**
project/render: it drains the posts the engine produced, then runs the polls.
The `FrameBody` trait lets the composition root attribute each phase.

## 7. The dispatch surface is the contract

Everything the TJS VM can reach — which classes exist and which members they
expose — is the frozen contract of this layer. It is measured by
`crates/compat/tests/runtime_surface.rs`, which asks the **live** VM what
`CompatHost::install` actually registered (rather than parsing Rust source)
and dumps it to `target/runtime_surface.json`, locked against the committed
baseline `docs/surface/runtime_surface.json`:

```bash
uv run --project scripts krkr-gate surface-lock            # regenerate + check
uv run --project scripts krkr-gate surface-lock --update   # accept a change
```

What that buys:

* **L3 is freely refactorable.** Any change that leaves the dump
  byte-identical cannot change how a call reaches a native, so internals,
  state layout and file organisation above this line are open ground.
* **Invented surface is blocked mechanically.** Adding a member the reference
  does not have changes the dump, fails the gate, and forces a new baseline
  into the same review — where the addition appears as a diff, not as a claim
  in a report.
* **Silent breakage is blocked too**: a member that disappears would fail
  dispatch at runtime, and it fails the same gate.

This is deliberately *not* a completeness measure. Parity answers "what is
missing?" and stays a report; the lock answers "what changed?", and behaviour
is constrained separately: every semantic must be cited to the reference.

### The one process-wide binding

The C++ ABI hands native callbacks only the raw `tjs2_engine*`; the `tjs`
crate exposes **no user-data slot**. This tree keeps exactly **one**
process-wide binding — an engine→context table in `compat` — because the ABI
forces it. It is L3 (never L1), it holds *dispatch* state (a reference to the
L2 session), never game state, and it is documented here. The stateless-L1
rule still holds for L1.

`CompatServices` attaches **raw pointers** to the shared L2 handles with
`attach_scene`, `attach_storage`, `attach_input` and `attach_timer`. The
attachment is `unsafe`: the pointed-to value must stay alive for as long as
the binding is installed. The accessors return the raw pointer, not a
reference — `CompatServices` cannot prove the L2 owner is still alive, so
forming a `&Scene` there would be an unsound shared reference. Natives
dereference under their own `unsafe` contract.

## 8. Script loading and error text

`Scripts.execStorage`/`evalStorage` read the named script through the L2
storage and offer the raw bytes to the TJS2 **bytecode loader first**; only
when the loader reports the input is not bytecode is it decoded as text,
which is the reference's order. Text decoding handles the `FE FE` cipher /
zlib container, a UTF-8/UTF-16 BOM, an explicit `Scripts.textEncoding`
override, then UTF-8 and CP932; an undecodable script raises a typed error
instead of producing mojibake.

A caught script error is formatted as `<block>(<line>): <message>`, so a
host-side failure names the failing script and line instead of only the raw
message.

## 9. Known gaps in L3

* **The L3 behavioural audit is open.** L1/L2 are small, stateless
  abstractions that the static gates cover well; the compatibility emulation
  is L3, where a member can exist with the right name and arity and still
  lose the reference semantics. Audit every L3 module against
  `reference/cpp/**` and give each script-observable path a behaviour test
  with a reference citation. The surface lock and the parity reports remain
  the contract but are **not** the evidence of behaviour.
* **35 of the 53 plugin names games ship have no emulation**, so each takes
  the null-plugin path. `PackinOne` is the one unemulated plugin real games
  actually link, so a storage proxy there needs behaviour, not surface;
  `krmovie`/`yuzuex` need L1/L2 backends. The order is in
  `plugins/analysis/PRIORITY.md`.
* **The in-game menu form is not drawn at all.** `MenuItem.popup` keeps the
  tree in the menu state and returns the reference's success value, but
  nothing draws the engine's own popup form, so a title that gates settings
  behind a popup leaves the player stuck.
* **The `WIN32Dialog` surface is incomplete** — only the class constructor
  and `messageBox` are installed; `Header`, `Items`, `Bitmap`, `Blob`,
  `SolidBrush`, the octet/string address members, `initCommonControlsEx` and
  the instance API remain.
* **`Window.registerMessageReceiver` records the receiver but nothing
  dispatches messages**, and the `windowEx` dynamic events (`onMinimize`,
  `onResizing`, …) are probed by name and never raised: there is no native
  window-message dispatcher on Linux.
* **`onCloseQuery` is registered as a no-op** and `CloseRequested` exits
  outright, so the reference's veto cannot happen.
* **Window-level `onMouseEnter`/`onMouseLeave`/`onDoubleClick` are
  synthesized** although the reference only declares them; `onMouseDown` does
  not first run `PrimaryMouseMove` and `onMouseUp` does not re-check the layer
  under the cursor. `Mouse`/`Key` are port-only. `PlayStatus` lacks
  `"ready"`.
* **`Window.useMouseKey` is stored and never acted on**, and
  `Window.postInputEvent` dispatches to the first window and its focused layer
  instead of `this` window.
* **IME and the on-screen keyboard are incomplete.** Linux splits the IME
  commit per character, with no xkb/keymap or dead-key handling;
  `Window.imeMode`/`Layer.imeMode` are stored and never acted on. Android
  **drops text input** entirely and never requests the soft keyboard, so a
  title that asks the player to type a name cannot.
* **`Layer.openMovie`/`startMovie` raise** where the reference logs and
  returns void, so a `try/catch` observes a different outcome.
* **`getVisBuffer` reads the decoded source**, not the device ring; a
  positive `sampleAhead` past the decoded end yields silence where the
  reference reads the ring.
* **Input is still flattened across focus domains.** Hit-testing walks the
  whole window's layer order where the reference binds input to manager
  index 0, so a click can reach a layer in a second root the reference would
  never deliver to. The scene has `window_input_root`; the dispatch does not
  use it.
* **`is_primary`/`primary_layer` is per window, not per manager**, so
  hiding or moving a *second* root does not raise the reference's
  `TVPCannotSetPrimaryInvisible`/`TVPCannotMovePrimaryOrSiblingless`.
* **`hasImage = true` must raise `TVPLayerCannotHaveImage`** when the layer
  type cannot carry an image; the three non-image types still collapse into
  `SourceOver` and the scene has no `can_have_image`.
* **`Font.rasterizer = n` raises for `n != 0`** where the reference ignores
  an out-of-range value, and `Font.getList(flags)` accepts `flags` and
  ignores it.
* **`Storages.addAutoPath` raises the wrong message** for a missing trailing
  delimiter — a script-observable difference.
* **`Storages.getFullPath`/`getPlacedPath`** return a normalized relative
  name or `arc>entry`, not the reference's full `file://domain/path`.
* **The `xp3_filter` buffer is a TJS `Array` carrying `ptr`/`count`**, and
  the filter script resolves free names against the game's global scope
  where the reference keeps them in a sub-engine, so a `global.x = …` there
  is visible to the game.
* **The vendored `reference/cpp/plugins/json/jsonPlugin.cpp` is a
  demonstration** (its `evalJSON` returns its input), so the port
  implements real JSON semantics through `serde_json` plus a byte-exact
  writer. That divergence needs its own record.
* **`dirlist` does not apply the reference's file-type filter**, the
  `windowEx` `ncht*` members are read-only where the reference registers
  writable data members, and the parity checker cannot see
  post-registration globals (`global.X = …`), so `getDirList`,
  `drawFFTGraph`, `FILE_ATTRIBUTE_*` and `ShortCutInitial*` have no coverage.
* **The comments-gate debt**: 4126 baseline entries over 170 files, and four
  files with `unsafe` blocks that carry no `SAFETY:` note.
