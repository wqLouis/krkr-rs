# L1 — the platform core

Status: **authoritative**. Describes `crates/platform/**` as it is today.

L1 is **mechanism**. It owns the Vulkan device, the FFmpeg/MediaCodec codecs,
the raw byte IO, the window, the event loop, the clock and the threads — and
nothing else. It knows nothing of layers, of TVP, of TJS, of storage
namespaces or of KAG. Every higher layer reaches it through the abstractions
below.

---

## 1. The object/state split

This is the load-bearing rule of L1.

* **L1 creates and owns the abstraction objects** — `FileSystem`,
  `RenderPipeline`, `Media`, `AudioDevice`, `FontSystem`, `PlatformWindow`.
  They are *services*: configuration only, no mutable field, no registry, no
  cache. Their methods take `&self`.
* **L2 stores every state value** — `RenderScene`, `RenderState`,
  `SurfaceState`, `FileState`, `AudioDecoderState`, `VideoDecoderState`,
  `GlyphAtlas`, the mixer, the caches, the indexes. Every one of them is
  defined by L1 and passed back into an L1 action as an explicit `&mut`
  argument.

```rust
pub fn render(
    p: &RenderPipeline,
    surface: &Surface,
    state: &mut RenderState,
    scene: &RenderScene,
) -> Result<Presentation, RenderError>;

pub fn read_at(fs: &FileSystem, file: &FileState, offset: u64, buf: &mut [u8])
    -> Result<usize, FsError>;
```

What L1 must never contain:

* mutable statics, `thread_local!`, `LazyLock`/`OnceLock`/`OnceCell`,
  `lazy_static!`, process-global registries, `Mutex<HashMap<…>>` caches;
* a `&mut self` method that remembers anything for a later call;
* hidden state between calls — the output depends only on the object's
  immutable configuration, the arguments and the passed-in state;
* policy: L1 does not cache, reuse, prefetch, coalesce, defer or throttle.
  Those are L2 decisions expressed in L2 state;
* callbacks into L2 — L1 returns owned data and L2 polls.

The review question is *"does this object remember anything?"* — if yes, it
belongs in a state value. The second question is *"could two engines run in
one process?"* — the answer must be yes.

Enforced by `uv run --project scripts krkr-gate stateless`.

### `api` — the shared DTO crate

`crates/platform/api` holds the types more than one L1 crate and L2 must
agree on, and nothing else: no implementations.

| module | contents |
|---|---|
| `api::blend` | `BlendMode` and the destination-dependent `DstBlend` family |
| `api::geometry` | `RectF`, `PixelRegion`, `Affine2`, `Transform2D` |
| `api::glyph` | `FontMetrics`, `GlyphBitmap`, `GlyphStyle` |
| `api::fs` | `FsPath`, `OpenMode`, `SeekFrom`, `FileStat`, `FileMetadata`, `DirEntry` |
| `api::media` | `ImageInfo`, `DecodedImage`, `AudioSpec`, `DecodedAudio`, `VideoSpec`, `RgbaFrame`, `MediaCapabilities` |

| `api::config` | the runtime configuration values (`CacheLimit`, `FrameRateLimit`, `RuntimeConfig`, …) |
| `api::error` | the typed error enums: `FsError`, `MediaError`, `RenderError`, `GlyphError`, `AudioError` |

## 2. `fs` — bytes in, bytes out

`crates/platform/fs` is a stateless root object plus positional IO.

```rust
pub struct FileSystem { /* backend kind + base */ }     // host root | memory root
pub struct FileState  { /* open handle + logical cursor */ }

pub fn open(fs: &FileSystem, path: &FsPath, mode: OpenMode) -> Result<FileState, FsError>;
pub fn stat(fs: &FileSystem, path: &FsPath) -> Result<FileStat, FsError>;
pub fn list(fs: &FileSystem, path: &FsPath) -> Result<Vec<DirEntry>, FsError>;
pub fn read_at(fs: &FileSystem, file: &FileState, offset: u64, buf: &mut [u8])
    -> Result<usize, FsError>;
pub fn write_at(fs: &FileSystem, file: &FileState, offset: u64, buf: &[u8])
    -> Result<usize, FsError>;
```

* The cursor lives inside `FileState`, which L2 owns. There is **one** byte-IO
  mechanism and **no** open-file registry.
* Positional reads are what make parallel media/image workers possible: two
  readers share a `FileState` without sharing a cursor.
* Backends: a **host path** root (`std::fs`, used for the game directory, the
  app-data directory and savedata) and an **in-memory** root (used by the
  engine's unit tests and the storage fixtures). `FsPath::Uri` exists in the
  API so a SAF/`ContentResolver` root can be added without an API change;
  **no SAF or asset backend is wired yet**.

### XP3 parsing

`fs::xp3` parses the XP3 container. Parsing is a pure transform over bytes,
so it belongs in L1; the *namespace* over the parsed index belongs in L2
([`l2.md`](l2.md) §5).

* `Xp3Archive` holds the base offset and the entry map — metadata only, no
  bytes, no file handle, no cursor.
* An `Entry` is metadata plus segment descriptors (`flags`, `start`,
  `org_size`, `arc_size`); the bytes stay in the archive file (or in the
  preloaded image) and a read is positional over the segment.
* `normalize_in_archive_name` is the shared name-normalisation rule, re-
  exported by the engine crate.

## 3. `render` — the render pipeline

`crates/platform/render` owns **all** render mechanism: scene-tree traversal,
parent transforms, z-order, opacity composition, clipping, blend-state
selection, batching, texture upload scheduling, offscreen compositing and
presentation. L2 hands it a tree; it draws it.

```rust
pub struct RenderPipeline { /* device, swapchain mechanism, shader library */ }
pub struct RenderState   { /* swapchain, staging, compiled pipelines, texture
                              table, offscreen targets, atlas uploads */ }
pub struct RenderScene   { pub root: RenderNodeId, pub nodes: Vec<RenderNode>,
                            pub background: Option<[f32; 4]> }
```

The pipeline is single-threaded on the host thread and is the **only** L1
object in the render path. Every mutable render thing lives in the
L2-owned `RenderState`.

### The draw tree

`render::scene` defines the tree L1 consumes and L2 owns:

* `RenderNode { parent, children, content, transform, dst, src, opacity,
  color, visible, z, blend, clip, hold_alpha }`
* `RenderContent` — `None` (container), `Solid([f32; 4])`, `Texture(Texture)`,
  `Glyphs(GlyphRun)`
* `Clip` — `Rect(RectF)` (axis-aligned scissor) or `Mask(Texture)` (alpha)
* `Transform2D` — translate / scale / rotation / pivot

Two free functions carry the space math and **both backends call them**, so
the backends cannot drift:

* `node_spaces(node, parent)` returns `(node_space, content_space)`. Because
  `dst` is placed *before* the node transform, a device-space `dst` scales the
  rectangle's origin and its extent together — the property a letterbox needs.
* `child_sort_key` / `children_are_sorted` keep sibling `z` ordering identical
  across backends; the common case (L2 appends children already in `z` order)
  iterates the borrowed slice without a clone and sort.

### Backends

| backend | file | role |
|---|---|---|
| **Vulkan** | `vulkan/mod.rs`, `vulkan/draw.rs` | the real renderer (`ash` 0.38, `ash-window`) |
| **Null / CPU** | `null.rs`, `cpu.rs` | the headless backend and the **correctness baseline** |

`Recorder::visit(id, parent_transform, parent_opacity, scissor, depth)`:

1. bounds-check the node, respect `visible`, multiply the opacity, skip when
   the composed opacity is ≤ 0;
2. `node_spaces` → `node_space` / `content_space`;
3. intersect the node's clip with the inherited scissor (`Clip::Rect` becomes
   a scissor, `Clip::Mask` is `RenderError::Unsupported`);
4. draw the payload (`Solid` or `Texture`; an unuploaded texture is skipped;
   `Glyphs` is `Unsupported`);
5. recurse into the children in `z` order.

Both backends are capped at `MAX_TRAVERSAL_DEPTH` (1024).

The null backend has two jobs: for the **framebuffer** it only *counts* the
draws (there is no window to show); for an **offscreen target** it runs the
real software rasterizer, which clears to `background`, walks the tree with
the same rules and samples each quad with nearest-texel filtering. Because a
CPU compositor naturally reads the destination, it evaluates the
destination-dependent `BlendMode`s exactly, using the reference's
Photoshop/KiriKiri formulas. The Vulkan backend reports them `Unsupported`
rather than substituting source-over.

### Blend states

Blend state is not a shader concern; it is a per-pipeline
`VkPipelineColorBlendAttachmentState`. `blend_slot` maps a `BlendMode` onto
seven fixed-function slots:

| `BlendMode` | Vulkan `srcColor` / `dstColor` / `op` |
|---|---|
| `SourceOver` | `SRC_ALPHA` / `ONE_MINUS_SRC_ALPHA` / `ADD` |
| `Replace` | `ONE` / `ZERO` / `ADD` |
| `Additive` | `SRC_ALPHA` / `ONE` / `ADD` |
| `Subtractive` | `SRC_ALPHA` / `ONE` / `REVERSE_SUBTRACT` |
| `AddAlpha` | additive colour, source alpha replaces destination alpha |
| `Multiply` | `DST_COLOR` / `ZERO` / `ADD` |
| `Screen` | `ONE_MINUS_DST_COLOR` / `ONE` / `ADD` |

The eleven destination-dependent modes (`DstBlend`: ColorDodge/5, ColorBurn,
Darken, Lighten, Difference/5, Exclusion, Overlay, HardLight, SoftLight) need
to read the destination colour, which fixed-function blend state cannot
express. They are **CPU-only today**. The Vulkan path for them is the
offscreen-compositing design: render to an offscreen target, copy the target
content for the quad's `dst` region into a sampled image, and draw with a
shader variant selected by `DstBlend`. That is also the mechanism a future
GPU transition would use.

Two base programs are prebuilt: a **textured quad** and a **solid quad**. The
pipeline set is built up front, so a frame never builds pipeline state.

### Textures and uploads

* L2 owns `BitmapState` (CPU RGBA) and its dirty flags.
* `upload_texture` writes a dirty sub-rectangle into a
  `VK_IMAGE_USAGE_TRANSFER_DST` image through a staging buffer;
  `upload_textures` batches every dirty sub-rectangle into one staging pass
  and one GPU wait.
* sRGB: images are `Rgba8Srgb` and colours are linearised in the shader. One
  format plus linear shader math, applied consistently across both backends.
* `drop_texture` is called when L2 drops a bitmap, so the bitmap→texture
  lifetime is explicit L2 state.

### Glyphs

`FontSystem` is the stateless abstraction, `Font` is immutable parsed data,
and `rasterize_glyph` produces CPU coverage. The atlas is L2 state. Text is
composited into the layer bitmap on the CPU, so `getPixel`, `piledCopy` and
`saveLayerImage` keep working. A GPU glyph path (`RenderContent::Glyphs`) is
**defined but not implemented**: both backends report
`RenderError::Unsupported` and `supports_glyph_atlas` is `false` everywhere.

### Presentation

The pipeline has **no** presentation policy. It receives device-space
rectangles and draws them. Fit-with-letterbox is L2's rule, applied during
the projection — see [`l2.md`](l2.md) §4.

The one thing the pipeline does own is the **acquire budget**: how long a
frame may wait for the display to release a swapchain image. It is two frame
periods, derived from the configured frame interval, and an unusable interval
is a typed error rather than a substituted wait. A frame whose image does not
arrive within the budget is **skipped**: the backend submits nothing, the
previous surface contents stay on screen, and it reports
`Presentation { presented: false, skip: Some(PresentSkip::AcquireTimeout) }`.
A skip is not a surface fault and is not retried inside the frame; L2 counts
it and reports it.

## 4. `media` — decode

`crates/platform/media` decodes images, audio and video. The mixer, the sound
object model, the `.sli` loops and every script semantic are L2/L3.

| concern | file |
|---|---|
| image decode (format sniffing + the `image` crate) | `image_decode.rs` |
| TLG5/TLG6 | `tlg.rs` |
| image encode (PNG/BMP/JPEG) | `image_encode.rs` |
| audio probe/decode/streaming | `audio.rs` |
| the platform audio fallback | `audio_ffmpeg.rs` |
| video decode | `video/ffmpeg.rs` (Linux), `video/mediacodec.rs` (Android) |
| YUV → RGBA8 | `yuv.rs` |

The API is stateless: pure free functions for image and whole-file audio
decode, and L1-defined `AudioDecoderState` / `VideoDecoderState` values owned
by L2 for streaming. There is no engine-side registry, no global buffer and no
hidden cache.

**Image decode order:** extension hint → magic sniff → decode. `probe_image`
returns the dimensions and the alpha/format flags without a full decode (it
backs `loadHeader`).

**Audio decode** is symphonia on both targets (wav/pcm, ogg/vorbis, flac,
mp3, mp4/aac) plus an Opus adapter. The built-in decoder has no SBR
synthesis, so an HE-AAC track declares 48 kHz while the decoder produces the
core's 24 kHz. The decoder **reports** that mismatch instead of playing the
track at the wrong speed: `open_audio` decodes the first packet so the report
happens at the open. The platform's own decoder then handles the track —
FFmpeg's AAC decoder on Linux, the platform's `audio/mp4a-latm` decoder on
Android. The host owns the choice: the built-in decoder is tried first, the
platform backend is the fallback, and when both fail the error names both
reasons. Silence is never substituted.

**Video decode** keeps the current `MovieDecoder` semantics as an L1-defined
`VideoDecoderState`:

* `open_video(&Media, Arc<[u8]>, Option<&str>) → (VideoSpec, VideoDecoderState)`;
* `present_video(&Media, &mut VideoDecoderState, at_ms) → RgbaFrame` with the
  backward-seek contract (seek when moving backwards past the tolerance,
  otherwise decode forward);
* `video_audio(&Media, &VideoDecoderState) → Arc<DecodedAudio>` — the track is
  shared, so a caller that plays it does not copy it;
* dropping the state releases the codec.

The audio side has the same shape: `probe_audio` and `decode_audio` are pure
free functions over bytes, while `open_audio` / `read_audio` /
`seek_audio` take a caller-owned `AudioDecoderState`.

The FFmpeg backend uses `ffmpeg-next` with an in-memory custom IO (no temp
file). It decodes the whole audio track eagerly at `open`; the decoded track
is handed out shared. A track with more than two channels is downmixed to
stereo, because the L2 mixer renders mono and stereo only — a documented
approximation against the reference, which keeps the file's channel count.

The MediaCodec backend uses `AMediaExtractor` + `AMediaCodec` over a `memfd`,
with byte-buffer output in `COLOR_FormatYUV420Flexible` and the pure-Rust
YUV conversion. `AMediaExtractor` is not covered by the `ndk` crate, so it
stays as a small raw shim.

### Backend selection

Exactly one video backend is compiled:

| feature | target | backend |
|---|---|---|
| `video-ffmpeg` (default) | Linux | system FFmpeg, linked dynamically through `pkg-config` |
| `video-mediacodec` | Android | NDK MediaCodec; links no FFmpeg |

Selecting neither or both is a `compile_error!`. FFmpeg is a **required
system dependency** on Linux and is not bundled.

## 5. `psd` — the PSB/PSD reader

`crates/platform/media/psd` is a separate workspace member (excluded from the
`media` package) that parses the PSB container and decodes a PSD image into
RGBA. It is stateless like every other L1 crate: a parse over bytes plus a
decode into an owned buffer.

It uses `forkunion` for the container and `fearless_simd` for the parallel
8-bit planar-to-RGBA and alpha passes. The SIMD dispatch is runtime-selected
and the thread pool is created per decode call and never cached.

It backs the PSB/PSD plugin natives and the motion player. `forkunion` has a
C++ core, so the host build compiles but the aarch64 Android build and run
are **unverified**.

## 6. `platform` — the host

`crates/platform/platform` owns the window, the event loop, the input
devices, the clock, the audio output and the process metrics. It is the only
crate with a `#[cfg(target_os)]`.

| concern | item |
|---|---|
| window / surface | `PlatformWindow`, `RawWindowHandle`/`RawDisplayHandle` projection |
| event loop | `run(config, handler)`, `EventHandler` |
| events | `PlatformEvent::{Resized, ScaleFactorChanged, CloseRequested, Focused, Input}` |
| input devices | `InputEvent`, `MouseButton`, `PhysicalKey` |
| clock | `Clock`, `Ticker`, `FramePacing` |
| audio output | `AudioDevice`, `AudioOutputState`, `AudioQueue` |
| fonts | `system_font_dirs`, `ANDROID_SYSTEM_FONT_DIRS` |
| metrics | `memory_usage`, `process_cpu_ns`, `process_io` |

### Compile-time platform selection

The platform is chosen at compile time; the other platform's code is not
compiled. Exactly one feature must be active and there is no default:

* `platform-linux` — the real `winit` 0.30 window/event-loop backend and the
  real `cpal` 0.16 audio-output backend;
* `platform-android` — the real AAudio output backend (via the `ndk` crate,
  Android 8.0 / API 26+) plus stubs for the window and event loop, whose
  `run` returns `PlatformError::NotImplemented`.

Enabling both or neither is a `compile_error!`, as is `platform-linux` on an
Android target. The Android composition root owns the `android-activity`
`GameActivity` loop and hands the `ANativeWindow` to the platform layer, so
`platform`'s own Android `run` is never called.

Everything that needs the NDK stays gated to `target_os = "android"`, so the
`platform-android` feature also compiles on a desktop host: the
platform-independent helpers and a typed stub build there, and the real
AAudio/window code builds only for an Android target. That is what the
`krkr-gate android-target` check resolves the dependency graph for.

### Audio output

`AudioDevice::open` returns the device and an `AudioOutputState`; `write`
pushes PCM into the queue the platform callback drains. The queue policy is
shared by every backend and lives in `audio_queue`: a 150 ms pre-fill before
the stream starts (inside a 100–250 ms window that suits a visual novel), a
two-second cap that drops the oldest samples first, and a 5 ms shared-gain
fade in and out of the per-channel hold on an underrun. `AudioDevice::null`
provides a headless device that applies the same policy without hardware.

The crate is `#![deny(unsafe_code)]`, not `forbid`: the `ndk` crate wraps the
AAudio C API safely, but its data callback hands the audio buffer over as a
raw `*mut c_void`, so one small private module converts that pointer into a
writable slice. That is the only `unsafe` in the crate, and it carries a
scoped `#[allow(unsafe_code)]` with a `SAFETY:` note on every block.

## 7. What L1 deliberately does not do

* storage namespaces, `.xp3` addressing, case rules, auto-path search —
  **L2** ([`l2.md`](l2.md) §5);
* the mixer, the sound object model, `.sli` loop metadata, fades, 3D
  attenuation — **L2**;
* the video-overlay state machine, timing anchors, event delivery — **L2**;
* decoded-asset and image caches, the glyph atlas, compiled pipelines —
  **L2**;
* TVP layer properties, masks, province, focus/hit-test, script callbacks —
  **L2** on top of the render tree, **L3** where the vocabulary is TVP;
* KAG, TJS values, exceptions, object registries — **L3**;
* the presentation policy — **L2**.

## 8. Known gaps in L1

* **Device-pixel readback is not wired.** The single backing is the
  device-resolution framebuffer, and a VM-pixel read should sample the device
  region `[x·s, (x+1)·s) × [y·s, (y+1)·s)`. The transports are designed
  (Android: an `AHardwareBuffer` allocated first and imported into Vulkan,
  read with `AHardwareBuffer_lock` over the region; desktop and fallback: a
  host-visible staging copy) but neither is implemented. Today the script
  reads the CPU layer bitmap, which is already VM-exact.
* **No GPU glyph path.** `RenderContent::Glyphs` is rejected by both
  backends and `supports_glyph_atlas` is `false` everywhere, so text is
  soft at `scale > 1` — a rasterization approximation, not a script-observable
  difference.
* **No destination-dependent blend on Vulkan.** The eleven `DstBlend` modes
  are CPU-only.
* **No mask clip and no per-layer affine transform** in the projection or the
  backends. `Clip::Mask` and `RenderError::Unsupported` cover the backend
  side; the projection does not emit either.
* **`create_render_target` / `read_render_target` are plumbed by neither
  `engine` nor `compat`**, so a capture-style API has no path to a rendered
  texture.
* **The Vulkan descriptor pool is a fixed cap.** It exhausts past roughly
  1024 live textures; the pool should be sized from the live texture count.
  The exit-time `free(): chunks in smallbin corrupted` abort is also open.
* **Android is compile-checked, never run.** No NDK is installed on the
  development host and none may be installed. The AAudio, MediaCodec and
  `AHardwareBuffer` paths are reviewed here and run on a machine that has an
  NDK; everything Android-only is documented as unverified.
* **The `AHardwareBuffer` route is the only one that can carry CPU reads.**
  The extension's own issue 4 is explicit that an imported Android hardware
  buffer need not support host-visible memory types, and `vkMapMemory` is not
  `AHardwareBuffer_lock`. The buffer must therefore be allocated first and
  imported into Vulkan, and read with `lock` (which returns the stride; a
  missing stride is a typed error, never an assumed width).
* **No SAF or `AssetManager` backend** in `fs`; `FsPath::Uri` is reserved.
* **The C++ `fopen` bypass.** `tjs/cpp/streams.cpp` implements TJS
  `Array.save`/`load`/`saveStruct` with `std::fopen` directly, outside the
  stateless fs surface. It is the only port-authored C++ besides the ABI
  shim, and it is a known Android/scoped-storage hazard.
